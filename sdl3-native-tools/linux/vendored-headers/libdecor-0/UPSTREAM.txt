sdl3-native-tools/linux/vendored-headers/libdecor-0 - VENDORED HEADER
================================================================================

WHAT THIS FOLDER IS
--------------------------------------------------------------------------------
libdecor's public header, unmodified, plus a pkg-config stub, so the linux-x64
and linux-arm64 builds can compile SDL's libdecor support (client-side window
decorations on Wayland compositors that do not draw them - GNOME / mutter,
Weston). The AlmaLinux 8 manylinux images used for those two RIDs do not
package libdecor-devel at all; the riscv64 image (Rocky Linux 10) does, and its
build ignores this folder.

Only the HEADER is needed. SDL is configured with SDL_DEPS_SHARED=ON
(SDL_WAYLAND_LIBDECOR_SHARED=ON): it dlopen()s libdecor-0.so.0 on the user's
machine at run time and links no libdecor library, so libdecor never appears
in the shipped library's NEEDED list (the gate checks it). No libdecor code is
compiled into SDL - the header contributes declarations, types and enum values.

Vendored by Jeremy's ruling, 2026-10-01 (GO on vendoring the libdecor header
and rebuilding linux-x64 and linux-arm64 with the libdecor backend).

0.2.2 is the same libdecor version the riscv64 image's libdecor-devel package
carries (libdecor-devel-0.2.2-5.el10), so all three Linux RIDs compile against
one libdecor API. SDL turns the pkg-config version into SDL_LIBDECOR_VERSION_*
= 0/2/2; with dynamic loading it resolves the post-0.1 functions as OPTIONAL
symbols, so the library still works with an older libdecor on the user's
machine and simply runs without decorations where there is none.

HOW THE BUILD USES IT
--------------------------------------------------------------------------------
linux/pins.env SDL_VENDORED_PKGCONFIG_<ARCH> names this folder for x64 and
arm64. container-build.sh prepends it to PKG_CONFIG_PATH and passes
-DDECOR_0_LIB=libdecor-0.so.0, the soname SDL then dlopen()s (SDL's
FindLibraryAndSONAME would otherwise search for a libdecor-0.so to read the
soname from, and there is deliberately none). BUILD-INFO.txt records the
result.

NOT MODIFIED
--------------------------------------------------------------------------------
libdecor.h is never edited. To move to a newer libdecor, fetch the new tag's
src/libdecor.h, replace the file, and update the tag, URL, sha256, size and date
above, the Version in libdecor-0.pc, and ../../../BUILD-PROVENANCE.txt.
